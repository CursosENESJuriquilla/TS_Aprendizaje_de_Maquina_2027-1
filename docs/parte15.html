15  Máquinas de soporte vectorial con más de dos clases

Hasta ahora hemos trabajado principalmente con problemas de clasificación binaria y datos sintéticos que nos permitían visualizar directamente las fronteras de decisión.

En esta práctica daremos un paso hacia un problema más realista.

Trabajaremos con:

  • más de dos clases;
  • múltiples variables predictoras;
  • variables medidas en escalas diferentes;
  • selección de hiperparámetros mediante validación cruzada.

Vamos a:

  • aplicar una SVM a un problema multiclase;
  • distinguir las estrategias one-versus-one y one-versus-rest;
  • construir un Pipeline que combine escalamiento y clasificación;
  • utilizar validación cruzada para evaluar configuraciones del modelo;
  • utilizar GridSearchCV para seleccionar hiperparámetros;
  • buscar conjuntamente \(C\), \(\gamma\) y el tipo de kernel;
  • interpretar best_params_ y best_score_;
  • mantener separado el conjunto de prueba durante la selección del modelo.

15.1 Antes de comenzar

Advertencia🧠 Pregunta

En una SVM con kernel RBF, ¿qué funciones cumplen \(C\) y \(\gamma\)?

TipSolución

Los dos hiperparámetros afectan el comportamiento del clasificador, pero no representan lo mismo.

En scikit-learn, \(C\) controla la penalización de las violaciones del margen.

De manera esquemática:

\[C\downarrow \quad\Longrightarrow\quad \text{mayor regularización}.\]

Por otro lado, \(\gamma\) controla el alcance de la influencia de las observaciones en el kernel RBF:

\[K(x,z) = \exp\left(-\gamma\|x-z\|^2\right).\]

Un \(\gamma\) pequeño produce una influencia más global, mientras que un \(\gamma\) grande produce una influencia más local.

Advertencia🧠 Pregunta

¿Por qué utilizamos StandardScaler antes de ajustar una SVM?

TipSolución

Las SVM dependen de la geometría del espacio de características.

Si una variable tiene una escala mucho mayor que otra, puede influir de manera desproporcionada en distancias y productos internos.

El escalamiento coloca las variables en escalas comparables.

Además, el escalamiento debe formar parte del Pipeline para que sus parámetros se estimen únicamente con los datos disponibles durante cada ajuste.

Advertencia🧠 Pregunta

¿Por qué no debemos probar diferentes valores de \(C\) y \(\gamma\) sobre el conjunto de prueba y seleccionar la combinación que produzca el mejor resultado?

TipSolución

Porque entonces estaríamos utilizando información del conjunto de prueba para seleccionar el modelo.

El conjunto de prueba dejaría de representar datos completamente nuevos.

Los hiperparámetros deben seleccionarse utilizando únicamente los datos de entrenamiento.

Para ello podemos utilizar validación cruzada.

El conjunto de prueba se reserva para la evaluación final.

Advertencia🧠 Pregunta

¿Por qué conviene revisar la distribución de las clases antes de construir el modelo?

Porque el número de observaciones por clase puede afectar la forma en que interpretamos las métricas de clasificación.

Advertencia🧠 Pregunta

¿Todas las variables se encuentran aproximadamente en la misma escala?

¿Qué problema podría causar esto en una SVM?

TipSolución

No.

Algunas variables presentan valores relativamente pequeños, mientras que otras pueden tomar valores mucho mayores.

Como las SVM dependen de la geometría del espacio de características, las variables con escalas grandes podrían tener una influencia desproporcionada.

Por ello utilizaremos StandardScaler como parte del flujo de modelado.

15.7 ¿Cómo utiliza una SVM más de dos clases?

Hasta ahora nuestras SVM distinguían entre dos clases.

Sin embargo, Wine contiene tres:

\[K=3.\]

Una estrategia consiste en construir clasificadores para cada par de clases.

Esta estrategia se conoce como one-versus-one u OvO.

Con \(K\) clases necesitamos

\[\frac{K(K-1)}{2}\]

clasificadores.

Para nuestro ejemplo:

\[\frac{3(3-1)}{2} = 3.\]

Los problemas binarios serían:

\[0\text{ vs. }1,\]

\[0\text{ vs. }2,\]

y

\[1\text{ vs. }2.\]

Otra estrategia posible es one-versus-rest u OvR.

En ese caso se construyen \(K\) clasificadores:

\[0\text{ vs. resto},\]

\[1\text{ vs. resto},\]

\[2\text{ vs. resto}.\]

Advertencia🧠 Pregunta

Si tenemos \(K=10\) clases, ¿cuántos clasificadores binarios requiere OvO y cuántos requiere OvR?

TipSolución

Para OvO:

\[\frac{K(K-1)}{2} = \frac{10(9)}{2} = 45.\]

Para OvR:

\[K=10.\]

Por tanto, OvO requiere 45 problemas binarios y OvR requiere 10.

15.8 Multiclase en SVC

SVC utiliza internamente una estrategia one-versus-one para el entrenamiento multiclase.

    (

            kernel="linear",
            C=1

Nota¿Ya resolvimos el problema?

Es posible que nuestra primera SVM lineal obtenga una exactitud de \(1\), es decir, que clasifique correctamente todas las observaciones del conjunto de entrenamiento.

Esto no significa que debamos detenernos ni que el modelo tenga un desempeño perfecto sobre cualquier observación futura.

El conjunto Wine es relativamente pequeño y sus clases pueden distinguirse bastante bien utilizando modelos lineales.

Nuestro objetivo en esta práctica no es necesariamente mejorar la exactitud, sino investigar cómo se utilizan las SVM en problemas con más de dos clases.

En particular, estudiaremos:

  • Cómo funciona la estrategia One-versus-One (OvO).
  • Cómo construir una estrategia One-versus-Rest (OvR).
  • Qué diferencias existen entre ambas estrategias.
  • Si una frontera más flexible, como la obtenida con un kernel RBF, realmente ofrece alguna ventaja.

Un modelo más complejo no necesariamente produce mejores resultados.

15.9 ¿Por qué un Pipeline?

Nuestro flujo tiene dos pasos:

\[X \longrightarrow \text{StandardScaler} \longrightarrow \text{SVC}.\]

El Pipeline permite tratar ambos pasos como un solo estimador.

Esto será especialmente importante durante la validación cruzada.

En cada partición de validación cruzada queremos que:

  1. StandardScaler se ajuste utilizando únicamente el subconjunto de entrenamiento;
  2. esos datos se transformen;
  3. la SVM se ajuste;
  4. el subconjunto de validación se transforme utilizando el escalador obtenido en el paso 1;
  5. el modelo se evalúe.

El Pipeline realiza este procedimiento automáticamente.

Advertencia🧠 Pregunta

¿Qué estaría mal en estandarizar todo X_train antes de realizar validación cruzada?

TipSolución

Si calculamos previamente la media y desviación estándar utilizando todo X_train, las observaciones que posteriormente funcionarán como validación ya habrán participado en el preprocesamiento.

Esto introduce fuga de información entre los pliegues.

Al incluir StandardScaler dentro del Pipeline, el escalamiento se vuelve a ajustar correctamente dentro de cada partición de validación cruzada.

Advertencia🧠 Pregunta

Supongamos que la mejor combinación fuera

C = 10
gamma = 0.1

¿Podemos concluir que estos valores serán los mejores para cualquier conjunto de datos?

TipSolución

No.

Los hiperparámetros seleccionados dependen de:

  • los datos;
  • las variables;
  • el preprocesamiento;
  • el kernel;
  • la métrica utilizada;
  • las particiones de validación cruzada.

No existe un valor universalmente óptimo de \(C\) o \(\gamma\).

15.18 ¿Podemos comparar diferentes kernels?

Sí.

Pero debemos tener cuidado: no todos los kernels utilizan los mismos hiperparámetros.

Por ejemplo:

  • linear utiliza \(C\);
  • rbf utiliza \(C\) y \(\gamma\);
  • poly utiliza \(C\), \(\gamma\), degree y potencialmente coef0.

Por ello no conviene definir una sola cuadrícula donde todos los parámetros se apliquen indiscriminadamente a todos los kernels.

Podemos utilizar una lista de diccionarios.

Código

            0.001,
