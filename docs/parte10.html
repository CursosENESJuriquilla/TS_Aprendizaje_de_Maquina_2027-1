10  Validación cruzada y optimización de hiperparámetros

En sección anterior modificamos manualmente diferentes hiperparámetros de Gradient Boosting y XGBoost.

Por ejemplo:

GradientBoostingRegressor(
    n_estimators=200,
    learning_rate=0.05,
    max_depth=2
)

Sin embargo, inmediatamente aparecieron dos problemas:

  1. nuestro resultado dependía de una única partición train–validation;
  2. probar manualmente muchas combinaciones de hiperparámetros resulta poco práctico.

Ahora vamos a explorar:

  • implementar \(k\)-fold Cross-Validation;
  • interpretar la media y variabilidad del desempeño entre folds;
  • utilizar KFold;
  • realizar una búsqueda sistemática con GridSearchCV;
  • realizar una búsqueda aleatoria con RandomizedSearchCV;
  • comparar el costo computacional de ambas estrategias;
  • integrar preprocesamiento y modelado mediante un Pipeline.

10.3 El problema de una única partición

Antes dividimos temporalmente el conjunto de entrenamiento en:

\[ \text{Train} \longrightarrow \begin{cases} \text{Train GB}\\ \text{Validation} \end{cases}. \]

Esto nos permitió comparar configuraciones.

Pero aparece una pregunta:

Advertencia🧠 Pregunta

¿Qué ocurre si cambiamos las observaciones que terminaron en el conjunto de validación?

Vamos a comprobarlo.

Definimos primero una configuración fija de Gradient Boosting.

Código 
modelo = GradientBoostingRegressor(
    n_estimators=200,
    learning_rate=0.05,
    max_depth=2,
    random_state=42
)

Ahora realizaremos varias divisiones cambiando únicamente la semilla aleatoria.

Código 
resultados_split = []

for semilla in [1, 10, 42, 100, 500]:

    X_tr, X_val, y_tr, y_val = train_test_split(
        X_train,
        y_train,
        test_size=0.20,
        random_state=semilla
    )

    modelo.fit(X_tr, y_tr)

    pred = modelo.predict(X_val)

    rmse = np.sqrt(
        mean_squared_error(y_val, pred)
    )

    resultados_split.append({
        "random_state": semilla,
        "RMSE": rmse
    })

10.4 \(k\)-fold Cross-Validation

En \(k\)-fold Cross-Validation dividimos los datos en \(k\) subconjuntos o folds:

\[ D_1,D_2,\ldots,D_k. \]

Cada fold se utiliza una vez como conjunto de validación y los restantes se utilizan para entrenamiento.

Por ejemplo, para \(k=5\) realizamos cinco entrenamientos.

El desempeño promedio es

\[ \overline{s}_{CV} = \frac{1}{k} \sum_{j=1}^{k}s_j. \]

También podemos estudiar su variabilidad mediante la desviación estándar.

10.5 Nuestro primer Cross-Validation

Crearemos una estrategia de 5-fold Cross-Validation.

Código 
cv = KFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

Utilizaremos el mismo Gradient Boosting:

Código 
modelo = GradientBoostingRegressor(
    n_estimators=200,
    learning_rate=0.05,
    max_depth=2,
    random_state=42
)

Ahora utilizamos cross_val_score().

Código 
scores = cross_val_score(
    modelo,
    X_train,
    y_train,
    cv=cv,
    scoring="neg_root_mean_squared_error"
)

Veamos el resultado:

Código 
scores
array([-0.58945794, -0.56738891, -0.5513569 , -0.58885872, -0.56687094])

Puede llamar la atención que los valores sean negativos.

Esto ocurre porque scikit-learn utiliza la convención de que un score mayor debe representar un mejor desempeño.

Sin embargo, RMSE es un error:

\[ \text{menor RMSE} \quad\Longrightarrow\quad \text{mejor}. \]

Por ello, scikit-learn devuelve:

\[ -\operatorname{RMSE}. \]

Para trabajar directamente con RMSE podemos cambiar el signo:

Código 
rmse_cv = -scores

rmse_cv
array([0.58945794, 0.56738891, 0.5513569 , 0.58885872, 0.56687094])

\[ \operatorname{RMSE}_{CV} = \overline{\operatorname{RMSE}} \pm SD. \]

La media nos informa sobre el desempeño promedio.

La desviación estándar nos ayuda a observar cuánto cambia el resultado entre diferentes particiones.

10.7 Comparando algunas configuraciones

Antes comparamos manualmente diferentes configuraciones.

Hagámoslo nuevamente, pero ahora utilizando Cross-Validation.

Consideremos:

Código 
configuraciones = [
    ("A", 0.1, 100, 2),
    ("B", 0.05, 200, 2),
    ("C", 0.01, 500, 2),
    ("D", 0.1, 100, 4)
]

Evaluaremos cada configuración con exactamente los mismos folds.

Código 
resultados_cv = []

for nombre, lr, n_est, depth in configuraciones:

    modelo = GradientBoostingRegressor(
        learning_rate=lr,
        n_estimators=n_est,
        max_depth=depth,
        random_state=42
    )

    scores = cross_val_score(
        modelo,
        X_train,
        y_train,
        cv=cv,
        scoring="neg_root_mean_squared_error"
    )

    rmse = -scores

    resultados_cv.append({
        "Modelo": nombre,
        "learning_rate": lr,
        "n_estimators": n_est,
        "max_depth": depth,
        "RMSE_CV": rmse.mean(),
        "SD_CV": rmse.std()
    })

Construimos una tabla.

10.8 El problema de la búsqueda manual

Hasta ahora evaluamos únicamente cuatro configuraciones.

Pero podríamos querer explorar:

\[ \texttt{learning\_rate} \in \{0.01,0.05,0.1\}, \]

\[ \texttt{n\_estimators} \in \{100,200,500\}, \]

y

\[ \texttt{max\_depth} \in \{2,3,4\}. \]

¿Cuántas configuraciones tenemos?

Código 
3 * 3 * 3
27

Son:

\[ 3\times3\times3=27 \]

configuraciones.

Pero cada configuración se evalúa mediante 5-fold Cross-Validation.

Por lo tanto:

Código 
27 * 5
135

necesitamos al menos

\[ 27\times5=135 \]

ajustes del modelo.

Escribir manualmente los ciclos necesarios sería posible, pero scikit-learn proporciona herramientas específicamente diseñadas para este proceso.

10.9 Grid Search

GridSearchCV evalúa sistemáticamente todas las combinaciones que especifiquemos.

Definimos primero nuestra cuadrícula.

Código 
param_grid = {
    "learning_rate": [0.01, 0.05, 0.1],
    "n_estimators": [100, 200, 500],
    "max_depth": [2, 3, 4]
}

Podemos calcular el número de configuraciones:

Código 
n_configuraciones = (
    len(param_grid["learning_rate"])
    * len(param_grid["n_estimators"])
    * len(param_grid["max_depth"])
)

print(n_configuraciones)
27

Construimos la búsqueda.

Código 
modelo = GradientBoostingRegressor(
    random_state=42
)

grid_search = GridSearchCV(
    estimator=modelo,
    param_grid=param_grid,
    scoring="neg_root_mean_squared_error",
    cv=cv,
    n_jobs=1,
    return_train_score=True
)

#grid_search.fit(X_train, y_train)
Notan_jobs=-1

Con n_jobs=-1, scikit-learn puede utilizar los procesadores disponibles para ejecutar parte del trabajo en paralelo.

Esto puede reducir considerablemente el tiempo de búsqueda. En una computadora de 32GB de ram y 12 CPUs, lo recomendable es n_jobs=4.

Esto motiva una estrategia diferente.

10.14 Random Search

En Random Search especificamos un espacio de búsqueda, pero evaluamos solamente un número determinado de configuraciones.

Por ejemplo, podemos decidir:

\[ B=20. \]

ajustes principales del modelo.

10.19 Preprocesamiento y Cross-Validation

California Housing tiene una ventaja para nuestro ejemplo de Gradient Boosting: los modelos basados en árboles no requieren estandarización para construir sus divisiones.

Pero imaginemos que utilizamos un modelo que sí depende de la escala de las variables.

Podríamos pensar en hacer(no correr):

scaler.fit(X_train)

X_train_scaled = scaler.transform(X_train)

cross_val_score(
    modelo,
    X_train_scaled,
    y_train,
    cv=cv
)

Sin embargo, existe un problema.

El escalador aprendió sus parámetros utilizando todo X_train antes de construir los folds.

Por ejemplo, StandardScaler utiliza

\[ z = \frac{x-\mu}{\sigma}. \]

Si calculamos \(\mu\) y \(\sigma\) utilizando todo X_train, las observaciones que posteriormente pertenecerán al validation fold ya participaron en el preprocesamiento.

Esto constituye una forma de data leakage.

10.20 Pipelines

La solución es incluir las transformaciones que aprenden de los datos dentro de un Pipeline.

Para ilustrarlo utilizaremos un modelo que ellos ya conocen: regresión lineal regularizada.

Código 
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Ridge

Construimos:

Código 
pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", Ridge())
])

Ahora realizamos Cross-Validation sobre todo el pipeline.

Código 
scores_ridge = cross_val_score(
    pipeline,
    X_train,
    y_train,
    cv=cv,
    scoring="neg_root_mean_squared_error"
)

rmse_ridge = -scores_ridge

print(
    f"RMSE CV: {rmse_ridge.mean():.4f} "
    f"+/- {rmse_ridge.std():.4f}"
)
RMSE CV: 0.7205 +/- 0.0139

Durante cada fold, scikit-learn realiza conceptualmente:

\[ \text{training fold} \]

\[ \downarrow \]

\[ \text{ajustar StandardScaler} \]

\[ \downarrow \]

\[ \text{transformar training fold} \]

\[ \downarrow \]

\[ \text{entrenar Ridge} \]

y solamente después utiliza esos parámetros para transformar el validation fold.
