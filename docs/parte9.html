9  Métodos modernos de Gradient Boosting

Vamos a utilizar Gradient Boosting para resolver un problema de regresión.

Intentaremos:

  • implementar un modelo de Gradient Boosting con scikit-learn;
  • interpretar los hiperparámetros n_estimators, learning_rate y max_depth;
  • estudiar cómo cambia el desempeño al modificar estos hiperparámetros;
  • visualizar cómo evoluciona el error conforme se agregan árboles al ensamble;
  • reconocer la relación entre el learning rate y el número de árboles.

Después utilizaremos estos resultados para introducir métodos modernos como XGBoost.

¿Qué observamos?

A medida que agregamos árboles, el ensamble intenta corregir los errores de los modelos anteriores.

En términos generales, el modelo después de \(m\) iteraciones tiene la forma

\[ F_m(\mathbf{x}) = F_{m-1}(\mathbf{x}) + \eta h_m(\mathbf{x}), \]

donde \(h_m(\mathbf{x})\) representa la corrección aprendida por el nuevo árbol y \(\eta\) es el learning rate.

9.6 Learning rate

El hiperparámetro learning_rate controla cuánto contribuye cada nuevo árbol al ensamble.

La actualización es

\[ F_m(\mathbf{x}) = F_{m-1}(\mathbf{x}) + \eta h_m(\mathbf{x}). \]

Si \(\eta\) es grande, cada árbol puede producir una corrección importante.

Si \(\eta\) es pequeño, las correcciones son más conservadoras.

Comparemos tres valores:

\[ \eta\in\{1,\;0.1,\;0.01\}. \]

Mantendremos inicialmente el mismo número de árboles.

TipSolución

Un modelo más complejo puede disminuir el error de entrenamiento simplemente porque tiene mayor capacidad para ajustarse a los datos.

Para decidir si esa complejidad realmente mejora la capacidad de generalización necesitamos evaluar el modelo sobre observaciones que no hayan participado en su entrenamiento.

Hasta ahora, hemos construido un modelo de Gradient Boosting y modificado manualmente tres de sus hiperparámetros principales:

\[ \boxed{ \texttt{learning\_rate}, \qquad \texttt{n\_estimators}, \qquad \texttt{max\_depth} } \]

Observamos que:

  1. agregar árboles permite realizar correcciones sucesivas;
  2. el learning_rate controla la magnitud de estas correcciones;
  3. un learning_rate pequeño suele requerir un mayor número de árboles;
  4. árboles más profundos aumentan la capacidad del modelo;
  5. los hiperparámetros interactúan entre sí;
  6. el error de entrenamiento no es suficiente para decidir qué configuración utilizar.

El número

\[ m^* = \arg\min_m \operatorname{RMSE}_{val}(m) \]

nos proporciona una posible elección del número de árboles.

ImportanteUna diferencia fundamental

El número de árboles que minimiza el error de entrenamiento no es necesariamente el que produce el mejor comportamiento sobre datos nuevos.

Por esta razón necesitamos alguna forma de validación.

9.12 Early stopping

La idea anterior conduce al concepto de early stopping.

En lugar de continuar agregando árboles indefinidamente, podemos detener el entrenamiento cuando el desempeño sobre validación deja de mejorar.

Conceptualmente buscamos una iteración \(m^*\) tal que

\[ m^* = \arg\min_m L_{\mathrm{val}}(F_m). \]

Una forma sencilla de hacerlo es:

  1. entrenar un número grande de árboles;
  2. observar el desempeño de validación en cada etapa;
  3. identificar el número adecuado de árboles;
  4. entrenar el modelo final utilizando ese número.

9.14 De Gradient Boosting a XGBoost

Hasta ahora hemos utilizado la implementación clásica de Gradient Boosting disponible en scikit-learn.

Ahora veremos una implementación moderna: XGBoost.

XGBoost conserva la idea fundamental de construir árboles secuencialmente para mejorar el ensamble, pero incorpora mecanismos adicionales de regularización y optimizaciones computacionales.

Ya vimos que su función objetivo puede representarse esquemáticamente como

\[ \mathcal{J} = \sum_{i=1}^{n} L(y_i,\widehat y_i) + \sum_{m=1}^{M}\Omega(h_m), \]

donde el primer término mide el error de predicción y \(\Omega(h_m)\) penaliza la complejidad de los árboles.
