11  Evaluación y comparación de modelos

En las secciones anteriores construimos modelos de Gradient Boosting y aprendimos a utilizar Cross-Validation para seleccionar hiperparámetros.

Ahora integraremos estos elementos dentro de un flujo completo de aprendizaje automático.

Al finalizar esta práctica seremos capaces de:

  • establecer una baseline;
  • comparar diferentes modelos utilizando los mismos folds;
  • analizar el desempeño promedio y su variabilidad;
  • realizar una optimización de hiperparámetros;
  • recuperar y reajustar el modelo seleccionado;
  • evaluar finalmente el procedimiento sobre el conjunto de prueba;
  • analizar predicciones y residuos.

Nuestro flujo de trabajo será:

\[ \boxed{\text{Datos}} \longrightarrow \boxed{\text{Train/Test}} \longrightarrow \boxed{\text{Cross-Validation}} \longrightarrow \boxed{\text{Comparación}} \longrightarrow \boxed{\text{Tuning}} \longrightarrow \boxed{\text{Refit}} \longrightarrow \boxed{\text{Evaluación final}}. \]

11.1 Preparación

Importamos las bibliotecas necesarias.

Código 
import numpy as np

    r2_score
)

11.3 Modelos que compararemos

Consideraremos cinco modelos:

Código 
modelos = {
    "Baseline": DummyRegressor(
        strategy="mean"
    ),

    "Linear Regression": LinearRegression(),

    "Decision Tree": DecisionTreeRegressor(
        random_state=42
    ),

    "Random Forest": RandomForestRegressor(
        n_estimators=200,
        random_state=42,
        n_jobs=1
    ),

    "Gradient Boosting": GradientBoostingRegressor(
        n_estimators=200,
        learning_rate=0.05,
        max_depth=2,
        random_state=42
    )
}

Observen que estamos comparando modelos con características muy diferentes.

Tenemos desde una baseline extremadamente sencilla hasta métodos de ensamble.

NotaPrimera comparación

En esta primera etapa no intentaremos optimizar exhaustivamente todos los modelos.

Queremos obtener una comparación inicial utilizando un procedimiento común de evaluación.

Posteriormente realizaremos tuning sobre algunos de los modelos.

11.4 Una estrategia común de Cross-Validation

Utilizaremos exactamente los mismos folds para todos los modelos.

Código 
cv = KFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

Esto significa que cada modelo será entrenado y evaluado sobre las mismas particiones.

Conceptualmente queremos:

\[ \boxed{ \text{mismos datos} + \text{mismos folds} + \text{mismas métricas} }. \]

11.5 Evaluaremos más de una métrica

Hasta ahora utilizamos principalmente RMSE.

En esta práctica utilizaremos:

  • MAE;
  • RMSE;
  • \(R^2\).

Definimos las métricas:

Código 
scoring = {
    "MAE": "neg_mean_absolute_error",
    "RMSE": "neg_root_mean_squared_error",
    "R2": "r2"
}

Recordemos que scikit-learn devuelve MAE y RMSE negativos cuando se utilizan como scores.

Esto permite mantener la convención

\[ \text{score mayor} \quad\Longrightarrow\quad \text{mejor}. \]

Después cambiaremos el signo para recuperar los errores en su interpretación habitual.

11.6 Comparación mediante Cross-Validation

Utilizaremos cross_validate().

A diferencia de cross_val_score(), esta función nos permite calcular varias métricas simultáneamente y registrar tiempos de entrenamiento.

Código 
resultados = []

for nombre, modelo in modelos.items():

    cv_result = cross_validate(
        modelo,
        X_train,
        y_train,
        cv=cv,
        scoring=scoring,
        n_jobs=1
    )

    resultados.append({
        "Modelo": nombre,

        "MAE_CV":
            -cv_result["test_MAE"].mean(),

        "MAE_SD":
            cv_result["test_MAE"].std(),

        "RMSE_CV":
            -cv_result["test_RMSE"].mean(),

        "RMSE_SD":
            cv_result["test_RMSE"].std(),

        "R2_CV":
            cv_result["test_R2"].mean(),

        "R2_SD":
            cv_result["test_R2"].std(),

        "Tiempo":
            cv_result["fit_time"].mean()
    })

Construimos una tabla.

df_resultados = pd.DataFrame(resultados)

11.7 ¿Cómo interpretamos la tabla?

Tenemos ahora información sobre tres aspectos:

\[ \boxed{\text{desempeño promedio}} \]

\[ \boxed{\text{variabilidad entre folds}} \]

\[ \boxed{\text{costo computacional}}. \]

Por ejemplo, el RMSE promedio se calcula como

\[ \overline{\operatorname{RMSE}} = \frac{1}{k} \sum_{j=1}^{k} \operatorname{RMSE}_j. \]

Mientras que RMSE_SD resume cuánto varían esos resultados entre folds.

Advertencia🧠 Discusión
  1. ¿Todos los modelos mejoran la baseline?
  2. ¿Los modelos con menor RMSE también presentan mayor \(R^2\)?
  3. ¿Cuál presenta mayor variabilidad entre folds?
  4. ¿Existen diferencias importantes en tiempo de entrenamiento?
  5. ¿Una diferencia pequeña en RMSE sería suficiente por sí sola para afirmar que dos procedimientos se comportan de manera sustancialmente distinta?

11.9 Observar los resultados fold por fold

La media puede ocultar información.

Comparemos, por ejemplo, Random Forest y Gradient Boosting.

Código 
modelos_comparar = {
    "Random Forest": modelos["Random Forest"],
    "Gradient Boosting": modelos["Gradient Boosting"]
}

scores_folds = []

for nombre, modelo in modelos_comparar.items():

    resultado = cross_validate(
        modelo,
        X_train,
        y_train,
        cv=cv,
        scoring="neg_root_mean_squared_error",
        n_jobs=1

        -resultado["test_score"],
        start=1

11.10 Comparar modelos no termina aquí

Hasta ahora hemos utilizado configuraciones razonables, pero no necesariamente optimizadas.

Por ejemplo, Gradient Boosting depende de

\[ \texttt{learning\_rate}, \qquad \texttt{n\_estimators}, \qquad \texttt{max\_depth}, \qquad \texttt{subsample}. \]

Random Forest también posee hiperparámetros como

\[ \texttt{n\_estimators}, \qquad \texttt{max\_depth}, \qquad \texttt{max\_features}, \qquad \texttt{min\_samples\_leaf}. \]

Por ello, una comparación más completa puede incluir un procedimiento de tuning.

Para mantener razonable el tiempo de cómputo realizaremos una búsqueda pequeña sobre estos dos modelos.

11.11 Tuning de Random Forest

Definimos un espacio de búsqueda.

Código 
param_rf = {
    "n_estimators": [100, 200, 400],
    "max_depth": [None, 10, 20, 30],
    "max_features": [0.5, 0.75, 1.0],
    "min_samples_leaf": [1, 2, 4]
}

Utilizaremos RandomizedSearchCV.

Código 
search_rf = RandomizedSearchCV(
    estimator=RandomForestRegressor(
        random_state=42,
        n_jobs=1
    ),
    param_distributions=param_rf,
    n_iter=12,
    scoring="neg_root_mean_squared_error",
    cv=cv,
    random_state=42,
    n_jobs=1
)

Ejecutamos:

Código 
inicio = perf_counter()

search_rf.fit(X_train, y_train)

tiempo_rf = perf_counter() - inicio

Consultamos los hiperparámetros seleccionados:

Código

TipTuning no garantiza una mejora enorme

La optimización de hiperparámetros puede mejorar el desempeño, pero no debemos esperar necesariamente cambios espectaculares.

11.14 El refit ya ocurrió

Recordemos que RandomizedSearchCV utiliza por defecto

refit=True

Después de seleccionar los hiperparámetros, vuelve a entrenar la configuración seleccionada utilizando todo el conjunto X_train.

Por ello tenemos disponibles:

Código 
modelo_rf_final = search_rf.best_estimator_
modelo_gb_final = search_gb.best_estimator_

Estos modelos ya fueron reajustados con todos los datos de entrenamiento.

Hasta este momento:

X_test
y_test

siguen sin participar en ninguna decisión.

11.15 Antes de abrir el test

Este es un momento importante del flujo de trabajo.

Ya realizamos:

  • comparación inicial;
  • Cross-Validation;
  • selección de hiperparámetros;
  • refit.

El conjunto de prueba no participó en ninguna de estas decisiones.

Nuestro esquema es:

\[ \boxed{ X_{\text{train}} } \longrightarrow \boxed{ \text{CV + comparación + tuning} } \longrightarrow \boxed{ \text{modelo ajustado} }. \]

Ahora sí podemos utilizar

\[ X_{\text{test}} \]

para obtener una evaluación final.

ImportanteUna vez abierto el test

No utilizaremos el resultado de test para volver a modificar repetidamente los hiperparámetros.

Si lo hiciéramos, el test comenzaría a funcionar como un nuevo conjunto de validación.

11.16 Evaluación final

En este ejemplo evaluaremos los dos procedimientos ajustados para observar su comportamiento sobre datos no utilizados durante el desarrollo.

Generamos predicciones:

Código 
pred_rf_test = modelo_rf_final.predict(
    X_test
)

pred_gb_test = modelo_gb_final.predict(
    X_test
)

Crearemos una función para calcular las métricas.

Código 
def metricas_regresion(y_real, y_pred):

    mae = mean_absolute_error(
        y_real,
        y_pred
    )

    rmse = np.sqrt(
        mean_squared_error(
            y_real,
            y_pred
        )
    )

    r2 = r2_score(
        y_real,
        y_pred
    )

    return mae, rmse, r2

Calculamos:

Código 
mae_rf, rmse_rf, r2_rf = metricas_regresion(
    y_test,
    pred_rf_test
)

mae_gb, rmse_gb, r2_gb = metricas_regresion(
    y_test,
    pred_gb_test
)

Construimos la tabla final.

Código 
resultados_test = pd.DataFrame({
    "Modelo": [
        "Random Forest",
        "Gradient Boosting"
    ],

    "MAE_test": [
        mae_rf,
        mae_gb
    ],

    "RMSE_test": [
        rmse_rf,
        rmse_gb
    ],

    "R2_test": [
        r2_rf,
        r2_gb
    ]
})

11.18 Predicho vs. observado

Una métrica resume el desempeño en un único número.

Pero también debemos observar las predicciones.

Tomemos uno de los modelos finales para ilustrar el diagnóstico. Por ejemplo, Gradient Boosting:

\[ \widehat y=y. \]

Predicciones perfectas caerían exactamente sobre esta línea.

11.19 Residuos

Definimos los residuos como

\[ e_i = y_i-\widehat y_i. \]

Calculamos:

Código 
residuos = y_test - pred_gb_test

Veamos su distribución.

Código 
plt.figure(figsize=(7, 4))

Código

Dos modelos pueden tener valores similares de RMSE y, sin embargo, cometer errores de maneras diferentes.

Por eso conviene complementar las métricas con visualizaciones y análisis del error.

11.20 ¿Dónde se equivoca más el modelo?

Podemos construir una tabla con las predicciones y sus errores.

Código 
diagnostico = X_test.copy()

diagnostico["y_real"] = y_test
diagnostico["y_pred"] = pred_gb_test
diagnostico["residuo"] = (
    diagnostico["y_real"]
    - diagnostico["y_pred"]
)

diagnostico["error_absoluto"] = (
    diagnostico["residuo"].abs()
)

Observemos las predicciones con mayor error absoluto.

Código 
diagnostico.sort_values(
    "error_absoluto",

11.22 El flujo completo

Ya podemos representar todo el procedimiento realizado durante las tres prácticas.

11.22.1 Paso 1: separar los datos

\[ \mathcal{D} \longrightarrow \boxed{ \mathcal{D}_{\text{train}} } + \boxed{ \mathcal{D}_{\text{test}} }. \]

11.22.2 Paso 2: trabajar solamente con train

Dentro de \(\mathcal{D}_{\text{train}}\) realizamos:

\[ \text{Cross-Validation} \longrightarrow \text{comparación} \longrightarrow \text{tuning}. \]

11.22.3 Paso 3: seleccionar hiperparámetros

Por ejemplo:

\[ \boldsymbol{\lambda}^{*} = \arg\min_{\boldsymbol{\lambda}} \operatorname{RMSE}_{CV}(\boldsymbol{\lambda}). \]

11.22.4 Paso 4: refit

El procedimiento seleccionado se vuelve a entrenar utilizando todo

\[ \mathcal{D}_{\text{train}}. \]

11.22.5 Paso 5: evaluación final

Finalmente:

\[ \widehat f^{*}(X_{\text{test}}) \]

permite calcular

\[ \operatorname{MAE}_{test}, \qquad \operatorname{RMSE}_{test}, \qquad R^2_{\text{test}}. \]

TipLa idea central de la unidad

El objetivo no es encontrar el modelo que produzca el número más pequeño en una tabla.

El objetivo es construir un procedimiento de evaluación en el que cada conjunto de datos tenga una función clara y donde las decisiones de modelado no contaminen la evaluación final.
