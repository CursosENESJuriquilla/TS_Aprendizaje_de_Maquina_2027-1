14  Máquinas de soporte vectorial

En las secciones anteriores construimos clasificadores de soporte vectorial con fronteras lineales.

El margen suave nos permitió trabajar con datos que no eran perfectamente separables. Sin embargo, la frontera continuó siendo de la forma

\[ \beta_0+\beta^Tx=0. \]

En esta práctica estudiaremos qué ocurre cuando la relación entre las clases es no lineal.

Ahora lo que exploraremos será:

  • reconocer situaciones en las que una frontera lineal es insuficiente;
  • explicar la idea de transformar el espacio de características;
  • interpretar el papel de un kernel;
  • distinguir entre kernel lineal, polinomial y radial;
  • interpretar el parámetro degree del kernel polinomial;
  • interpretar el parámetro \(\gamma\) del kernel RBF;
  • distinguir el efecto de \(C\) del efecto de \(\gamma\);
  • reconocer situaciones de subajuste y sobreajuste a partir de la frontera de decisión;
  • utilizar Pipeline para combinar escalamiento y SVM.

14.1 Antes de comenzar

Advertencia🧠 Pregunta

¿Qué controla el parámetro \(C\) en SVC?

TipSolución

En scikit-learn, \(C\) controla la penalización asociada con las violaciones del margen.

De manera general,

\[ C\downarrow \]

implica mayor regularización y mayor tolerancia a violaciones, mientras que

\[ C\uparrow \]

penaliza más fuertemente las violaciones y permite un ajuste más rígido a los datos de entrenamiento.

Advertencia🧠 Pregunta

¿Introducir un margen suave convierte automáticamente una frontera lineal en una frontera no lineal?

TipSolución

No.

El margen suave permite violaciones, pero si utilizamos un kernel lineal la frontera continúa siendo lineal:

\[ \beta_0+\beta^Tx=0. \]

Para obtener fronteras no lineales necesitamos ampliar la representación de las características.

Advertencia🧠 Pregunta

Supongamos que una clase se encuentra aproximadamente dentro de un círculo y la otra alrededor de ella.

¿Esperarías que una recta pudiera separar correctamente ambas clases?

TipSolución

No.

La estructura de separación es no lineal.

Una recta no puede encerrar una región del plano, por lo que necesitamos una frontera más flexible.

14.3 Función para visualizar fronteras no lineales

La función utilizada en las prácticas anteriores estaba diseñada principalmente para fronteras lineales.

Ahora construiremos una función más general.

Código 
def graficar_frontera(
    modelo,
    X,
    y,
    titulo="Frontera de decisión",
    mostrar_soporte=True
):
    
    plt.figure(figsize=(8, 6))
    
    x_min = X[:, 0].min() - 0.8
    x_max = X[:, 0].max() + 0.8
    
    y_min = X[:, 1].min() - 0.8
    y_max = X[:, 1].max() + 0.8
    
    xx, yy = np.meshgrid(
        np.linspace(x_min, x_max, 400),
        np.linspace(y_min, y_max, 400)
    )
    
    grid = np.c_[xx.ravel(), yy.ravel()]
    
    Z = modelo.decision_function(grid)
    Z = Z.reshape(xx.shape)
    
    plt.contourf(
        xx,
        yy,
        Z,
        levels=[Z.min(), 0, Z.max()],
        alpha=0.15
    )
    
    plt.contour(
        xx,
        yy,
        Z,
        levels=[-1, 0, 1],
        linestyles=["--", "-", "--"]
    )
    
    for clase in np.unique(y):
        plt.scatter(
            X[y == clase, 0],
            X[y == clase, 1],
            label=f"Clase {clase}",
            s=60
        )
    
    if mostrar_soporte:
        plt.scatter(
            modelo.support_vectors_[:, 0],
            modelo.support_vectors_[:, 1],
            s=160,
            facecolors="none",
            edgecolors="black",
            linewidths=1.4,
            label="Vectores de soporte"
        )
    
    plt.xlabel("$X_1$")
    plt.ylabel("$X_2$")
    plt.title(titulo)
    plt.legend()
    plt.show()
NotaNota

En las gráficas:

  • la línea continua representa la frontera de decisión \(f(x)=0\);
  • las líneas discontinuas representan \(f(x)=-1\) y \(f(x)=1\);
  • los círculos exteriores identifican los vectores de soporte.

Advertencia🧠 Para pensar

Antes de ajustar cualquier modelo:

  1. ¿Las clases parecen separables mediante una recta?
  2. ¿Qué forma aproximada debería tener una frontera adecuada?
  3. ¿Crees que aumentar mucho \(C\) resolvería el problema utilizando un kernel lineal?
TipSolución
  1. No. La estructura de las dos clases es curva.
  2. Necesitamos una frontera que pueda seguir aproximadamente esa curvatura.
  3. No. Aumentar \(C\) modifica la penalización de las violaciones, pero no cambia el hecho de que el kernel lineal produce una frontera lineal.

Este último punto es especialmente importante:

\[ \boxed{ C\text{ controla regularización, no la forma básica de una frontera lineal.} } \]

Para visualizar la frontera necesitamos tener cuidado: el Pipeline recibe datos en la escala original y realiza internamente la transformación.

Construiremos una función que pueda utilizar directamente un Pipeline.

Código 
def graficar_modelo(
    modelo,
    X,
    y,
    titulo="Frontera de decisión"
):
    
    # Crear figura
    plt.figure(figsize=(8, 6))
    
    # Límites de la región que vamos a visualizar
    x_min = X[:, 0].min() - 0.8
    x_max = X[:, 0].max() + 0.8
    
    y_min = X[:, 1].min() - 0.8
    y_max = X[:, 1].max() + 0.8
    
    # Crear una malla de puntos
    xx, yy = np.meshgrid(
        np.linspace(x_min, x_max, 400),
        np.linspace(y_min, y_max, 400)
    )
    
    # Convertir la malla en pares (X1, X2)
    grid = np.c_[
        xx.ravel(),
        yy.ravel()
    ]
    
    # Predecir la clase de cada punto de la malla
    Z_pred = modelo.predict(grid)
    
    # Regresar al formato de la malla
    Z_pred = Z_pred.reshape(xx.shape)
    
    # Colorear las regiones según la clase predicha
    plt.contourf(
        xx,
        yy,
        Z_pred,
        alpha=0.15
    )

    # Evaluar la función de decisión en toda la malla
    Z_decision = modelo.decision_function(grid)
    
    # Esta función está pensada para clasificación binaria
    Z_decision = Z_decision.reshape(xx.shape)
    
    # Sólo incluimos niveles que realmente estén dentro
    # del rango de la función de decisión
    niveles = [
        nivel
        for nivel in [-1, 0, 1]
        if Z_decision.min() <= nivel <= Z_decision.max()
    ]
    
    # Dibujamos los niveles únicamente si existen
    if len(niveles) > 0:
        
        estilos = [
            "-" if nivel == 0 else "--"
            for nivel in niveles
        ]
        
        plt.contour(
            xx,
            yy,
            Z_decision,
            levels=niveles,
            linestyles=estilos
        )
    
    for clase in np.unique(y):
        
        plt.scatter(
            X[y == clase, 0],
            X[y == clase, 1],
            label=f"Clase {clase}",
            s=60
        )

¿El problema principal parece ser que el modelo está permitiendo demasiadas violaciones o que la forma de la frontera es demasiado restrictiva?

TipSolución

El problema fundamental es la forma de la frontera.

Una recta no puede seguir adecuadamente la estructura curva de los datos.

Por tanto, necesitamos aumentar la flexibilidad de la frontera.

14.6 De variables originales a nuevas características

Una posibilidad sería crear explícitamente nuevas características.

Por ejemplo, partiendo de

\[ (x_1,x_2), \]

podríamos construir

\[ (x_1,x_2,x_1^2,x_2^2,x_1x_2). \]

En ese nuevo espacio podríamos ajustar un clasificador lineal.

Aunque el clasificador sería lineal respecto de las nuevas características, la frontera resultante podría ser no lineal respecto de \(x_1\) y \(x_2\).

Conceptualmente:

\[ x \longrightarrow \phi(x) \longrightarrow \text{clasificador lineal}. \]

Sin embargo, si tenemos muchas variables y utilizamos transformaciones complejas, el número de características puede crecer rápidamente.

Los kernels proporcionan otra forma de realizar esta idea.

14.7 Recordatorio: el truco del kernel

Un kernel puede interpretarse como una función

\[ K(x,z) \]

que calcula un producto interno en algún espacio de características transformado:

\[ K(x,z) = \langle\phi(x),\phi(z)\rangle. \]

La ventaja es que podemos calcular \(K(x,z)\) sin construir explícitamente todas las componentes de

\[ \phi(x). \]

Esta idea se conoce como el truco del kernel.

En esta práctica compararemos tres kernels:

\[ \text{lineal}, \qquad \text{polinomial}, \qquad \text{RBF}. \]

14.8 Kernel polinomial

Una forma del kernel polinomial es

\[ K(x,z) = (\gamma x^Tz+r)^d, \]

donde:

  • \(d\) controla el grado del polinomio;
  • \(\gamma\) escala el producto interno;
  • \(r\) es un término independiente.

En SVC, estos parámetros corresponden a:

degree
gamma
coef0

14.10 Kernel radial o RBF

Uno de los kernels más utilizados es el kernel radial:

\[ K(x,z) = \exp \left( -\gamma\|x-z\|^2 \right). \]

La similitud depende de la distancia entre las observaciones.

Si

\[ x\approx z, \]

entonces

\[ \|x-z\|^2\approx0 \]

y

\[ K(x,z)\approx1. \]

Si las observaciones están muy alejadas,

\[ K(x,z)\approx0. \]

Por tanto, el kernel RBF permite construir una clasificación basada en relaciones locales entre observaciones.

14.12 ¿Qué controla \(\gamma\)?

Recordemos:

\[ K(x,z) = \exp \left( -\gamma\|x-z\|^2 \right). \]

Si \(\gamma\) es pequeño, la similitud disminuye lentamente con la distancia.

Por tanto, cada observación tiene una influencia relativamente amplia.

Si \(\gamma\) es grande, la similitud disminuye rápidamente.

Entonces la influencia se vuelve mucho más localizada.

De manera esquemática:

\[ \boxed{ \gamma\downarrow \Rightarrow \text{influencia más global} } \]

y

\[ \boxed{ \gamma\uparrow \Rightarrow \text{influencia más local}. } \]

Veamos qué significa esto en la práctica.

¿Modificar \(C\) y modificar \(\gamma\) producen exactamente el mismo efecto?

TipSolución

No.

Ambos parámetros afectan la complejidad final del clasificador, pero tienen interpretaciones diferentes.

\(C\) controla la penalización de las violaciones:

\[ C\downarrow \Rightarrow \text{mayor regularización}. \]

\(\gamma\) controla qué tan local es la influencia de cada observación en el kernel RBF:

\[ \gamma\downarrow \Rightarrow \text{influencia más global}, \]

\[ \gamma\uparrow \Rightarrow \text{influencia más local}. \]

Por ello debemos considerar ambos hiperparámetros al construir una SVM con kernel RBF.

14.20 ¿Qué kernel debemos utilizar?

Después de estos experimentos podría ser tentador concluir que el kernel RBF siempre es preferible porque es más flexible.

Esto sería incorrecto.

Una mayor flexibilidad no implica automáticamente mejor capacidad predictiva.

Un kernel lineal puede ser suficiente cuando la estructura de separación es aproximadamente lineal.

Un kernel polinomial puede ser útil cuando una estructura de ese tipo representa adecuadamente la relación entre las variables.

El kernel RBF permite fronteras muy flexibles, pero introduce también el hiperparámetro \(\gamma\) y puede sobreajustar.

Por tanto, la elección del kernel y de sus hiperparámetros debe realizarse utilizando información de entrenamiento, generalmente mediante validación cruzada.

AdvertenciaNo utilices el conjunto de prueba para elegir el kernel

No debemos:

  1. ajustar varios kernels;
  2. comparar sus resultados en test;
  3. elegir el que obtuvo el mayor resultado en test.

Eso convertiría al conjunto de prueba en parte del proceso de selección del modelo.

En una evaluación correctamente diseñada, el conjunto de prueba se reserva para la evaluación final.
