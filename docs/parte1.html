1  Introducción al Aprendizaje Automático”

1.1 Objetivo del ejercicio

Este ejercicio es muy introductorio, solo se busca mostrar un ejemplo del flujo de trabajo que mencionamos usando un problema simple y datos simulados.

Al terminar este ejercicio se buscará responder:

  • ¿Qué etapas sigue un proyecto típico de aprendizaje automático?
  • ¿Por qué el escalamiento y la imputación se ajustan solo con el conjunto de entrenamiento?
  • ¿Por qué la exactitud (accuracy) puede ser una métrica engañosa?

Diapositivas

1.2 Planteamiento del problema

Etapa 1 del flujo de trabajo: formular la pregunta como un problema de regresión, clasificación, agrupamiento, etc.

Trabajaremos con un problema de regresión: predecir el precio de una vivienda (en miles de pesos) a partir de cuatro variables sencillas:

Variable Descripción
superficie Superficie construida, en m²
habitaciones Número de habitaciones
ciudad Ciudad donde se ubica la vivienda (categórica)
antiguedad Antigüedad de la vivienda, en años

1.3 Generación de los datos

Etapa 2 del flujo de trabajo: recolectar los datos relevantes, documentando su procedencia. Aquí, la “procedencia” es que los generamos nosotros con un modelo conocido, lo que también nos servirá para verificar al final si el resultado del modelo entrenado tiene sentido.

import numpy as np
import pandas as pd

rng = np.random.default_rng(42)
n = 300

superficie = rng.normal(90, 25, size=n).clip(30, None)          # m^2
habitaciones = rng.integers(1, 6, size=n).astype(float)
ciudad = rng.choice(["Xalapa", "CDMX", "Monterrey"], size=n,
                     p=[0.5, 0.3, 0.2])
antiguedad = rng.integers(0, 40, size=n).astype(float)           # años

# Precio "verdadero" simulado: relacion lineal + ruido aleatorio
bonus_ciudad = pd.Series(ciudad).map(
    {"Xalapa": 0, "CDMX": 450, "Monterrey": 200}).to_numpy()

precio = (
    15 * superficie
    + 80 * habitaciones
    - 3 * antiguedad
    + bonus_ciudad
    + rng.normal(0, 150, size=n)
)

df = pd.DataFrame({
    "superficie": superficie,
    "habitaciones": habitaciones,
    "ciudad": ciudad,
    "antiguedad": antiguedad,
    "precio": precio,
})

# Introducimos valores faltantes A PROPOSITO8
faltantes_idx = rng.choice(df.index, size=20, replace=False)
df.loc[faltantes_idx, "habitaciones"] = np.nan

df.head()
Tip¿Por qué metemos valores faltantes a propósito?

En un curso, rara vez los datos de juguete vienen con la imperfección de los datos reales (duplicados, faltantes, atípicos). Aquí los introducimos deliberadamente para poder practicar las técnicas de imputación dedatos, no porque sea buena práctica “ensuciar” datos en un proyecto real.

AdvertenciaUn principio que no debes olvidar

Cualquier transformación que dependa de estadísticos de los datos (media, desviación estándar, categorías observadas) debe ajustarse exclusivamente con el conjunto de entrenamiento. Ajustarla con todos los datos antes de particionar produce fuga de información e infla artificialmente el desempeño reportado.

1.9 (Opcional) Validación cruzada

Validación cruzada: cuando el conjunto es de tamaño moderado, la validación cruzada de \(k\) particiones aprovecha mejor los datos disponibles que una sola partición fija de validación.

from sklearn.model_selection import cross_val_score, KFold

kf = KFold(n_splits=5, shuffle=True, random_state=0)
puntajes = cross_val_score(
    modelo, X_train, y_train, cv=kf,
    scoring="neg_root_mean_squared_error")

print(f"RMSE promedio (CV, 5-fold): {-puntajes.mean():.2f}")

1.10 Bonus: clasificación con clases desbalanceadas

Clases desbalanceadas: convertimos el mismo problema en uno de clasificación binaria —¿la vivienda es “cara”?— para ilustrar por qué la exactitud puede ser engañosa cuando las clases están desbalanceadas.

Definimos como “cara” a una vivienda dentro del 15% más caro del conjunto, lo que genera un desbalance deliberado (≈85% / 15%).

from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (accuracy_score, precision_score,
                              recall_score, f1_score, confusion_matrix)

umbral = df["precio"].quantile(0.85)
y_clase = (df["precio"] >= umbral).astype(int)

Xc_train, Xc_test, yc_train, yc_test = train_test_split(
    X, y_clase, test_size=0.2, random_state=0, stratify=y_clase)

clasificador = Pipeline([
    ("preprocesamiento", preprocesador),
    ("clasificador", LogisticRegression(class_weight="balanced")),
])
clasificador.fit(Xc_train, yc_train)
yc_pred = clasificador.predict(Xc_test)

print("Matriz de confusión:\n", confusion_matrix(yc_test, yc_pred))
print("Exactitud :", round(accuracy_score(yc_test, yc_pred), 3))
print("Precisión :", round(precision_score(yc_test, yc_pred), 3))
print("Recall    :", round(recall_score(yc_test, yc_pred), 3))
print("F1        :", round(f1_score(yc_test, yc_pred), 3))
ImportanteEl punto clave

Un modelo “tonto” que siempre predijera “no es cara” tendría alrededor de 85% de exactitud, sin ninguna utilidad práctica. Por eso, ante clases desbalanceadas, conviene reportar precisión, recall, F1 o AUC-PR en vez de (o además de) la exactitud.

TipPara seguir practicando

Cuando te sientas cómodo con este flujo, intenta:

  • Cambiar Ridge por LinearRegression o RandomForestRegressor y comparar el \(R^2\).
  • Variar el parámetro alpha de Ridge y observar cómo cambia el error de entrenamiento vs. el de prueba (relaciónalo con la Sección 1.3 y 1.4).
  • Cambiar el umbral de la sección de clasificación (por ejemplo, al 50%) y ver cómo cambian precisión y recall al reducirse el desbalance.
